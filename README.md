# 음성녹음 (VoiceRecorder)

Kotlin + Jetpack Compose로 만든 간단한 폴더 기반 음성녹음 앱입니다.

## 주요 기능
- **홈 화면**: 폴더 목록 + `폴더 추가` 버튼 + `녹음` 버튼
- 폴더를 탭하면 해당 폴더 안의 녹음파일 목록 화면으로 이동
- **폴더 안에 들어간 상태에서 녹음 버튼을 누르면** 녹음이 시작되고,
  정지 시 파일명이 `[해당 폴더 이름]_[녹음 시작 시각].m4a` 형식으로 저장됩니다.
  - 예: `회의록` 폴더에서 2026년 7월 10일 14시 32분 5초에 녹음을 시작하면
    → `회의록_20260710_143205.m4a`
- **폴더를 고르지 않은 채 녹음 버튼을 누르면 `기본 폴더` 를 만들어 그 안에 녹음합니다.**
  (예전에는 "먼저 폴더를 선택해주세요" 안내만 떴습니다)
  - 태블릿처럼 넓은 화면에서는 앱을 켜면 `기본 폴더` 가 자동으로 열려 있어, 곧바로 녹음할 수 있습니다.
  - 서버(daglo)도 폴더를 지정하지 않은 녹음을 같은 이름의 폴더로 모으므로 이름이 맞춰져 있습니다.
- **녹음은 포그라운드 서비스(Foreground Service)로 동작**하기 때문에, 화면을 끄거나
  다른 앱으로 전환하거나 앱을 최소화해도 녹음이 계속됩니다. 녹음 중에는 상태 표시줄에
  진행 시간이 표시되는 알림이 뜨고, 알림의 `정지` 버튼으로도 녹음을 끝낼 수 있습니다.
  (알림을 강제로 스와이프해서 지우는 것만으로는 녹음이 멈추지 않습니다 - 앱으로 돌아오거나
  알림의 정지 버튼을 눌러야 종료됩니다.)
- 녹음 파일은 **`내부 저장소 > Recordings > Voice Recorder > [폴더명]`** 에 저장되어,
  기본 파일 관리자 앱 등에서도 바로 찾아볼 수 있습니다.
  - Android 10(API 29) 이상: `MediaStore`(Scoped Storage) API로 저장하므로 별도의 저장소 권한이 필요 없습니다.
    단, 빈 폴더(아직 녹음이 하나도 없는 폴더)는 앱 안에서만 표시되고, 파일 관리자에는 첫 녹음이 저장된 후에 폴더가 나타납니다.
  - Android 9(API 28) 이하: 실제 디렉터리로 바로 생성되며, `저장소` 권한(WRITE_EXTERNAL_STORAGE) 허용이 필요합니다.
- **기존에 있던 폴더/녹음파일도 자동으로 불러옵니다.**
  - 이전 버전의 앱(앱 전용 저장소에 저장하던 버전)을 쓰고 있었다면, 최초 실행 시 자동으로
    지금의 공용 저장 위치로 옮겨줍니다.
  - 다른 앱이나 파일 관리자로 `Recordings/Voice Recorder` 폴더 안에 미리 넣어둔 파일이 있다면,
    앱 실행 시 요청하는 **저장소 읽기 권한**(Android 13+: `READ_MEDIA_AUDIO`, Android 10~12:
    `READ_EXTERNAL_STORAGE`)을 허용하면 그 파일들도 함께 표시됩니다.
  - **하위 폴더 없이 `Recordings/Voice Recorder` 바로 아래에 있는 파일**(일부 제조사 기본 녹음 앱이
    이렇게 저장합니다)은 `Voice Recorder`라는 이름의 폴더로 목록에 표시됩니다.
- **앱을 열거나 다시 화면에 돌아올 때마다 자동으로 새로고침됩니다.** 파일탐색기 등 앱 밖에서
  폴더를 만들거나 파일을 옮기거나 지웠다면 그 변경사항이 반영됩니다.
  - 예를 들어 `ㅁㅁ` 폴더 안의 파일들을 파일탐색기에서 밖으로 빼내도, 폴더 자체가 파일탐색기에
    남아있는 한 앱에서도 계속 `ㅁㅁ` 폴더로 보입니다 (MediaStore 색인뿐 아니라 실제 파일시스템도
    함께 확인하기 때문입니다).
- **폴더/녹음파일 이름을 길게 누르면** "이름 변경" 버튼이 있는 메뉴가 뜨고,
  눌러서 새 이름을 입력하면 바로 변경됩니다.
  - 우리 앱이 만들지 않은 파일(다른 앱이 저장한 파일 등)의 이름을 바꾸는 경우,
    Android 11 이상에서는 시스템이 "이 항목들을 수정하도록 허용하시겠습니까?" 같은
    승인 다이얼로그를 띄웁니다. 허용하면 이름이 바뀌고, 거부하면 그 파일은 원래 이름/폴더에
    그대로 남습니다 (이전처럼 일부만 옮겨져서 예전 폴더가 찌꺼기로 남는 문제를 방지합니다).
  - 폴더 이름을 바꿔서 안의 파일들이 모두 새 폴더로 옮겨지면, 파일탐색기에 빈 폴더로
    남지 않도록 예전 디렉터리 자체도 함께 정리(삭제)합니다.
- **녹음파일을 탭하면 바로 재생됩니다.** 재생 중인 파일을 다시 탭하면 정지하고,
  재생이 끝까지 진행되면 자동으로 정지 상태로 돌아갑니다.
- **폴더를 길게 누르면 "삭제" 메뉴도 있습니다.** 누르면 확인 다이얼로그가 뜨고,
  확인하면 폴더와 그 안의 녹음파일이 전부 삭제됩니다 (되돌릴 수 없으니 주의하세요).
  이름 변경과 마찬가지로, 다른 앱이 만든 파일이 섞여 있으면 삭제 전에 시스템 승인
  다이얼로그가 한 번 더 뜰 수 있습니다.
- **녹음파일도 길게 누르면 "삭제" 메뉴가 있습니다.** 파일 하나만 골라서 지울 수 있고,
  마찬가지로 삭제 전 확인 다이얼로그가 뜹니다. 폴더 안의 마지막 파일을 지워서 파일이
  0개가 되어도 폴더 자체는 계속 목록에 남아있습니다 (폴더가 사라지길 원하면 폴더를
  길게 눌러 직접 삭제하면 되고, 그때는 파일탐색기의 실제 빈 디렉터리도 함께 정리됩니다).
- **녹음은 조각(segment)으로 나눠 안전하게 기록됩니다.** 녹음 중에는 앱 전용 저장소에 약 17분
  단위의 조각 파일로 쌓고, 정지할 때 하나의 m4a 로 합쳐 `Recordings/Voice Recorder` 에 넣습니다.
  - m4a 는 정지 시점에 파일 색인(moov)을 쓰기 때문에, 예전 방식으로는 3시간 녹음 중 앱이 죽으면
    파일 전체가 재생 불가가 되었습니다. 조각으로 끊어 두면 이미 닫힌 조각은 온전합니다.
  - **녹음 도중 앱이 죽어도 다음에 앱을 켜면 남은 조각을 자동으로 합쳐 되살립니다.**
  - 합치기는 다시 인코딩하지 않고 옮겨 담기만 하므로(re-mux) 음질 손실이 없고 몇 초면 끝납니다.
    혹시 합치기에 실패하면 조각을 `..._1of3.m4a` 처럼 따로 저장해서라도 소리를 남깁니다.
- **일시정지 / 재개를 지원합니다.** 쉬는 시간에 파일을 나누지 않고 이어서 녹음할 수 있고,
  일시정지한 시간은 녹음 길이에 포함되지 않습니다. 알림에서도 바로 누를 수 있습니다.
- **녹음 중 마이크 입력 레벨이 표시됩니다.** 마이크가 막혔거나 소리가 안 들어오는 것을
  3시간 뒤가 아니라 바로 알 수 있습니다.
- **녹음이 도중에 끊기면 즉시 알려줍니다.** (인코더 오류·저장공간 부족 등) 그때까지 녹음된
  내용은 버리지 않고 저장합니다.
- **녹음 정지 버튼을 누르면 바로 멈추지 않고 "정말 정지하시겠습니까?" 확인을 한 번 거칩니다.**
  실수로 정지 버튼을 눌러 녹음이 끊기는 걸 방지합니다. (단, 알림의 `정지` 버튼은
  확인 없이 바로 정지되니 주의하세요 — 시스템 알림에서는 앱 다이얼로그를 띄울 수 없어서
  이 버튼만은 즉시 정지로 남겨두었습니다.)

## 열기 / 실행 방법
1. Android Studio (최신 버전 권장, Hedgehog 이상)에서 `VoiceRecorder` 폴더를 **Open**으로 엽니다.
2. Gradle Sync가 끝날 때까지 기다립니다. (처음 열 때 Gradle wrapper jar를
   자동으로 내려받습니다. 인터넷 연결이 필요합니다.)
3. 실제 기기 또는 마이크가 동작하는 에뮬레이터를 연결하고 Run ▶ 을 누릅니다.
4. 앱 실행 후 녹음 버튼을 처음 누르면 마이크 권한을 요청합니다. 허용해주세요.

## 프로젝트 구조
```
app/src/main/java/com/recorder/voicenote/
 ├─ MainActivity.kt        # 전체 Compose UI (홈 화면 / 폴더 상세 화면)
 ├─ RecorderViewModel.kt   # 화면 상태 관리 (폴더 선택, 녹음 상태, 타이머 등)
 ├─ RecordingStore.kt      # 폴더/녹음파일 저장, 조회, 이름변경 (MediaStore / 레거시 파일 저장 분기)
 ├─ RecorderManager.kt     # MediaRecorder 래퍼 (조각 녹음/일시정지/오류 감지/입력 레벨)
 ├─ RecordingSession.kt    # 녹음 한 건의 작업 폴더 (조각 파일 + 메타)
 ├─ AudioMerger.kt         # 조각 m4a 를 하나로 합치기 (MediaExtractor/MediaMuxer, 재인코딩 없음)
 ├─ RecordingSaver.kt      # 합치기 → 공용 저장소 저장 → 업로드, 중단된 녹음 복구
 ├─ RecordingService.kt    # 백그라운드에서도 녹음을 유지하는 포그라운드 서비스
 ├─ PlayerManager.kt       # 녹음파일 재생을 담당하는 MediaPlayer 래퍼
 ├─ DagloSettings.kt       # daglo 서버 주소 / API 토큰 / 자동 업로드 설정 저장
 ├─ DagloApi.kt            # 서버 통신 (연결 확인, 녹음 파일 multipart 업로드)
 ├─ UploadWorker.kt        # WorkManager 업로드 작업 (네트워크 생길 때까지 대기 후 재시도)
 ├─ DagloScreens.kt        # 서버 설정 화면 + 앱 안에서 여는 daglo 웹 화면
 └─ ui/theme/              # Compose 색상 / 타이포그래피 테마
```

## daglo 서버와 연동해서 쓰기 (태블릿 권장)

같은 저장소의 `server/` 에 들어 있는 daglo 서버(FastAPI)와 붙여 쓰면,
**녹음 → 자동 업로드 → AI 받아쓰기 → 태블릿에서 스크립트 확인**까지 한 번에 이어집니다.
갤럭시 탭 S8 같은 태블릿에서 특히 쓸 만합니다 (넓은 화면에서 폴더 목록과 녹음 목록이 좌우로 함께 열립니다).

### 1. 서버 준비
1. PC 에서 서버를 켭니다.
   ```bash
   python run_server.py
   ```
2. 서버 `.env` 에 앱이 쓸 토큰을 넣고 서버를 재시작합니다. (없으면 앱에서 업로드가 401 로 거부됩니다)
   ```
   DAGLO_API_TOKEN=아무도-모를-긴-문자열
   HOST=0.0.0.0
   ```
3. PC 의 내부 IP 를 확인합니다. (`ipconfig` → IPv4 주소, 예: `192.168.0.10`)
   태블릿과 **같은 와이파이**에 있어야 합니다.

### 2. 앱 설정
1. 앱 오른쪽 위 톱니바퀴(⚙) → **daglo 서버 연결**
2. 입력
   - **서버 주소**: `192.168.0.10:8000` (`http://` 는 생략해도 됩니다)
   - **API 토큰**: 위에서 넣은 `DAGLO_API_TOKEN` 과 같은 값
   - **녹음 후 자동 업로드**: 켜 두기
3. `연결 테스트` 로 "서버에 연결됐습니다" 가 뜨는지 확인하고 `저장`

### 3. 쓰는 법
- **녹음이 끝나면 자동으로 올라갑니다.** 서버가 꺼져 있거나 와이파이가 끊겨 있으면 실패로 끝나지 않고,
  연결이 생길 때까지 기다렸다가 알아서 다시 올립니다. (앱을 껐다 켜도 유지됩니다)
- 개별 파일을 다시 올리려면 녹음 파일을 **길게 눌러 `daglo 서버로 보내기`** 를 선택하세요.
- 앱 오른쪽 위 지구본(🌐) 아이콘을 누르면 **앱 안에서 daglo 화면**이 열립니다.
  변환된 스크립트 편집, 요약, AI 채팅, 용어집, 다시 받아쓰기를 그대로 쓸 수 있습니다.
  (웹과 같은 계정으로 한 번 로그인하면 유지됩니다. 로그인 주소는 서버 `.env` 의 `LOGIN_PATH` 를 따릅니다)
- 앱 폴더 이름이 서버 폴더 이름이 됩니다. 서버에 같은 이름이 없으면 자동으로 만들어집니다.

### 웹에서 폴더 지우기
왼쪽 폴더 목록에서 폴더 위에 마우스를 올리면 나오는 휴지통 아이콘을 누릅니다.
안에 보드가 있으면 어떻게 할지 고를 수 있습니다.

| 고른 것 | 서버 동작 |
|---|---|
| 보드는 기본 폴더로 | 보드를 살려서 `기본 폴더` 로 옮깁니다. 원본 녹음과 변환 텍스트(동반 파일 포함)도 함께 옮겨집니다 |
| 보드도 휴지통으로 | 보드를 휴지통으로 보냅니다. 파일은 `휴지통` 폴더로 옮겨지므로 **휴지통에서 복원하면 원래 자리로 되돌아옵니다** |

- 탐색기의 폴더(`녹음파일원본`·`강의 녹음 변환` 양쪽)도 함께 정리합니다. 파일을 남겨 두면
  감시 스레드가 그 파일을 보고 지운 폴더를 곧바로 다시 만들어 내기 때문입니다.
- 서버가 모르는 파일이 남아 있으면 그 폴더는 지우지 않고 그대로 둡니다 (직접 넣어 둔 파일일 수 있으므로).
  이때는 화면에 몇 개가 남았는지 알려 줍니다.
- `기본 폴더` 는 지울 수 없습니다. 폴더 전용 용어집은 폴더와 함께 정리됩니다.

### 서버 폴더를 탐색기에서 직접 건드릴 때
서버 PC 의 `녹음파일원본` 폴더는 탐색기로 그냥 만지셔도 됩니다. 서버가 5초마다 확인해서 반영합니다.
기다리기 싫으면 웹 화면 오른쪽 위 **`새로고침`** 버튼을 누르세요. 그 자리에서 폴더를 한 번 훑어
새 녹음·이름변경·이동·삭제를 바로 목록에 반영합니다. (버튼을 연달아 눌러도 보드가 중복으로 생기지 않습니다)

| 탐색기에서 한 일 | 서버 동작 |
|---|---|
| 녹음 파일을 넣음 | 새 보드로 등록하고 자동으로 받아쓰기 시작 (복사가 끝난 것을 확인한 뒤) |
| 파일 이름 변경 | **같은 보드의 제목만 바뀝니다.** 다시 받아쓰지 않고 기존 스크립트를 그대로 유지 |
| 다른 폴더로 이동 | **같은 보드가 그 폴더로 따라갑니다.** 역시 다시 받아쓰지 않습니다 |
| 파일 삭제 | 보드를 휴지통으로 보냅니다 (연속 3회 안 보일 때 — 네트워크 드라이브가 잠깐 끊긴 것과 구분). `.env` 에서 `FILE_DELETE_SYNC=permanent` 로 두면 보드와 변환 텍스트(`.txt`·`_강의스크립트.html`)까지 곧바로 완전 삭제합니다 |
| 지웠던 파일을 다시 넣음 | 휴지통에서 보드를 되살립니다 |

- 이름변경/이동은 파일의 **수정시각**이 같은 것을 단서로 알아냅니다. 같은 시각의 후보가 둘 이상이면
  안전하게 새 보드로 등록합니다.
- 변환 결과 텍스트(`강의 녹음 변환/...`)는 예전 이름 그대로 남습니다. 웹에서 보는 스크립트는
  DB 에 있으므로 영향이 없습니다.
- 한 번의 확인에서 너무 많은 파일이 사라졌다면(기본 50개) 저장소 장애로 보고 아무것도 지우지 않습니다.

> 집 안 LAN 의 `http://` 서버로 접속하기 위해 앱은 평문 HTTP 를 허용합니다(`usesCleartextTraffic`).
> 서버를 인터넷에 열어 둔다면 HTTPS(리버스 프록시)와 `COOKIE_SECURE=1` 사용을 권장합니다.

## APK 만들기

### 방법 A. Android Studio에서 바로 만들기 (가장 간단)
1. Android Studio에서 프로젝트를 엽니다.
2. 상단 메뉴 `Build` → `Build Bundle(s) / APK(s)` → `Build APK(s)` 클릭.
3. 빌드가 끝나면 우측 아래 알림에 뜨는 `locate` 링크를 클릭하면
   `app/build/outputs/apk/debug/app-debug.apk` 파일을 바로 찾을 수 있습니다.
4. 이 apk 파일을 폰으로 옮겨서 설치하면 됩니다. (출처를 알 수 없는 앱 설치 허용 필요)

### 방법 B. GitHub에 올려서 자동으로 APK 만들기 (Android Studio 없이 가능)
이 프로젝트에는 이미 `.github/workflows/build-apk.yml` 이 포함되어 있어서,
GitHub에 올리기만 하면 자동으로 APK를 빌드해줍니다.

1. **새 저장소 만들기**
   - GitHub 로그인 → 우측 상단 `+` → `New repository`
   - 이름 입력(예: `voice-recorder`) 후 `Create repository` (Public/Private 상관없음)

2. **프로젝트 업로드**
   - 방금 만든 빈 저장소 페이지에서 `uploading an existing file` 링크 클릭
   - 압축 푼 `VoiceRecorder` 폴더 안의 내용 전체(모든 파일/폴더)를
     드래그 앤 드롭으로 업로드 (크롬/엣지 등 최신 브라우저는 폴더째 드래그 가능)
   - 하단 `Commit changes` 클릭
   - (터미널 사용이 익숙하다면 아래처럼 git으로 올려도 됩니다)
     ```bash
     cd VoiceRecorder
     git init
     git add .
     git commit -m "init"
     git branch -M main
     git remote add origin https://github.com/사용자명/voice-recorder.git
     git push -u origin main
     ```

3. **자동 빌드 확인**
   - 저장소 상단 메뉴의 `Actions` 탭 클릭
   - `Build Debug APK` 워크플로우가 자동으로 실행 중인 것을 확인 (초록 체크가 뜰 때까지 1~3분 대기)

4. **APK 다운로드**
   - 완료된 워크플로우 실행(런) 클릭 → 페이지 하단 `Artifacts` 항목에서
     `VoiceRecorder-debug-apk` 클릭 → zip 파일이 다운로드됨
   - 압축을 풀면 안에 `app-debug.apk` 파일이 들어있습니다. 폰에 옮겨 설치하세요.

> 참고: 이 워크플로우는 서명되지 않은 **디버그 APK**를 만듭니다. 테스트/개인 설치용으로는
> 문제없이 설치·실행되지만, Play 스토어에 올리려면 별도로 릴리즈 서명이 필요합니다.
