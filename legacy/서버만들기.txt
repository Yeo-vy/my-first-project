지금까지 겪으신 시행착오와 해결 과정, 그리고 시스템이 어떻게 진화해 왔는지 아주 상세하게 기록한 총정리 타임라인입니다.

처음 서버를 배포하고 계정을 설정하던 순간부터, 완벽한 무손실 비동기 처리 구조를 완성하기까지의 모든 여정이 담겨 있습니다.

* 1단계: Azure VM 생성 및 계정/권한 최적화
* **가상 머신 배포:** Azure 환경에서 Ubuntu Linux 기반의 인스턴스(`yeovyVM`)를 성공적으로 생성하고 SSH 접속 환경을 구축했습니다.
* **계정 혼선 해결:** 초기 접속 시 `azureuser`라는 기본 계정과 `yeovy` 계정이 혼재되어 헷갈리는 상황이 있었습니다. `/etc/passwd` 시스템 파일을 직접 조회하여 `yeovy` 계정의 존재를 확인하고, 이후 모든 작업을 실사용자인 `yeovy` 계정 하나로 통일했습니다.
* **Sudo 권한 최적화:** 서버 관리 중 매번 비밀번호를 입력해야 하는 번거로움을 없애기 위해 `visudo`를 수정하여 `NOPASSWD` 설정을 적용, 쾌적한 관리 환경을 만들었습니다.


* 2단계: 투트랙(Web/PC) 파일 스토리지 시스템 구축
* **Filebrowser (웹 스토리지):** 서버 내부에 `~/my_files` 디렉터리를 만들고, 이를 웹 브라우저에서 접근할 수 있도록 Filebrowser를 설치했습니다. 8080 포트를 개방하고 `systemd` 서비스(`filebrowser.service`)로 등록해 24시간 언제든 웹으로 접속해 파일을 관리할 수 있게 되었습니다.
* **RaiDrive (PC 네트워크 드라이브):** SSH(22번 포트)를 활용하는 SFTP 프로토콜을 통해, 내 Windows PC의 파일 탐색기에서 서버의 `my_files` 폴더를 마치 로컬 C/D 드라이브처럼 직접 열고 파일을 넣고 뺄 수 있도록 연동했습니다.


* 3단계: AI 오디오 변환을 위한 백엔드 환경 세팅
* **시스템 의존성 해결:** 음성 파일(.m4a, .mp4 등)을 쪼개고 변환하기 위한 핵심 엔진인 `FFmpeg`를 리눅스 패키지 관리자(`apt`)를 통해 시스템 자체에 설치했습니다.
* **Python 라이브러리 설치:** `ModuleNotFoundError` 에러를 디버깅하여 `python3-pip`를 설치한 뒤, Google Gemini API 구동을 위한 `google-genai`, 환경 변수 관리를 위한 `python-dotenv`, 오디오 처리를 위한 `pydub`를 일괄 세팅했습니다.
* **경고 메시지 필터링:** 파이썬 실행 시 발생하는 Gemini API의 AFC(Automatic Function Calling) 권장 사항 경고 로그를 `warnings.filterwarnings`를 통해 무시하도록 처리하여 로그 가독성을 높였습니다.


* 4단계: 파일 자동 감지 데몬(file-watcher) 초기 구축
* **inotify-tools 도입:** 리눅스 커널 수준에서 파일의 움직임을 감지하는 `inotifywait`를 사용해 `watch.sh` 스크립트를 작성했습니다.
* **이벤트 타겟팅:** 하위 폴더 재귀 감시(`-r`) 및 대상 확장자(`mp4, m4a, mp3, wav`) 필터링, 그리고 파일이 완전히 복사되거나 이동했을 때(`close_write`, `moved_to`)를 정확히 타겟팅했습니다.
* **서비스화:** SSH 터미널을 꺼도 감시가 멈추지 않도록 `file-watcher.service` 데몬으로 등록하고, `journalctl`을 통해 실시간 로그를 모니터링하는 체계를 잡았습니다.


* 5단계: Timezone(시간대) 동기화
* **UTC -> KST 변경:** 로그에 찍히는 시간이 현재 시간과 9시간 차이가 나는 것을 발견하고, Azure 서버의 기본 시간대인 UTC(세계 협정시)를 `Asia/Seoul`(한국 시간)로 변경하여 파일 생성 시간과 로그 기록 시간을 완벽히 일치시켰습니다.


* 6단계: 스크립트 로직 고도화 및 최적화 (가장 중요한 작업)
* **문제 1 (동기식 병목):** 처음엔 파일 1개가 변환되는 동안 뒤에 올라온 파일이 대기열에서 누락되는 문제가 있었습니다.
* **문제 2 (중복 실행 폭주):** 비동기(`&`)로 넘겼더니, SFTP 복사 특성상 이벤트가 여러 번 터지며 똑같은 파일에 대해 파이썬 스크립트가 3~10개씩 켜져 서버 과부하가 발생했습니다.
* **해결책 (Debounce + Mutex Lock):**
1. `TRIGGER_FILE`을 도입하여 파일이 업로드되는 동안은 '5초 대기 타이머'를 계속 리셋합니다. (Debounce)
2. 10개든 50개든 업로드가 완전히 멈추고 5초가 지나면, 비로소 파이썬 스크립트를 실행합니다.
3. `LOCK_FILE`을 도입해 파이썬이 돌고 있는 상태(사용 중)에서는 새 이벤트가 겹쳐도 중복 실행되지 않도록 원천 차단했습니다.
